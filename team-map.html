How we start

1

Sayed builds the skeleton

Run the prompt in E7-9 with Claude Code. It creates every folder and empty file. Review, then push to GitHub.

git init
git add .
git commit -m "E7-9: project skeleton"
git branch -M main
git remote add origin <repo-url>
git push -u origin main
2

Protect main

On GitHub: Settings → Branches → rule for main: require a pull request, 1 approval, and passing checks. Add Amr and Abdallah as collaborators.

3

Amr and Abdallah clone

Once, on each laptop. Everyone now has the same folders.

git clone <repo-url>
cd e7gz-ps
4

One branch per task

Start from fresh main, paste the Jira prompt into Claude Code, review the diff, open a PR. A teammate reviews, then squash-merge.

git switch main && git pull
git switch -c E7-15-command-runner
# ...work with Claude Code...
git add . && git commit -m "E7-15: command runner"
git push -u origin HEAD

Everyday rules

Stay in your folders

Each task lists where it writes. Need a change in someone else's folder? Ask them in the daily sync.

Frontend one sprint behind

Sayed and Amr build sprint N's backend; Abdallah builds sprint N−1's screens on the real API. Sayed still publishes each sprint's endpoints as stubs on day 2.

Waiting on a task?

Don't stop. Seed the database with test rows or use the mock, and keep going.

Review first

Before starting new work each morning, review teammates' open PRs. No PR waits more than a day.

Pull main daily

git pull --rebase origin main on your branch every morning keeps conflicts small.

Free AI tools

Abdallah: run node tools/ai-context/bundle.mjs E7-xx and give the file to Gemini or a browser chat — it carries CLAUDE.md and the task.

Product questions go to Sayed

A rule, a message or a timer you're unsure of? Ask, never guess. Answers go into docs/.
